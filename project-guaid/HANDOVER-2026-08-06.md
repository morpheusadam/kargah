## 2. 🔴 A credential in a request URL was reaching the database and a page

This is the most important thing in this document. It was live, it was not hypothetical, and one of
the two paths was worse than the trap the 5 August handover recorded.

**The mechanism.** Guzzle builds a `ConnectionException` message by appending the whole **effective**
request URI. Every publisher caught it and passed `$e->getMessage()` straight into `PublishFailed`.
`PostPublisher` writes that to `post_targets.error` and the posts page renders it. `SocialAccount`'s
three layers of credential hiding protect a *model*; none of them applies to a request URL.

**Two live leaks, not one.**

1. **Telegram**, which the last handover named. Its bot token is a **path segment** —
   `api.telegram.org/bot<token>/sendMessage` — and the Bot API offers no header scheme and no
   parameter scheme to move it to. VK's per-driver fix (move the token into a form body, see
   `VkPublisher::vkSend()`) is therefore unavailable here. Any timed-out send leaked a working token.
2. 🔴 **The Meta family, which nobody had noticed, and it is the worse of the two.**
   `MetaGraph::graphBody()` has **its own** catch site and does not go through `HttpPublisher` at
   all, so a fix in the base class would not have reached it. All three Meta `verify()` calls —
   Facebook Pages, Instagram, Threads — send the access token as a `$fields` entry on a **GET**,
   which Laravel appends as a query string. And `⚡account-connect` catches `PublishFailed` and
   renders `getMessage()` into both the check result **and** a toast. So a slow credential check
   printed a working Page or Instagram token on screen, at the exact moment somebody is pasting
   credentials in and most likely to screenshot the page. The publish paths were always safe: they
   are POSTs and the token rides in the body, which `MetaGraph::graphSend()` says deliberately.

**The fix: `HttpPublisher::cannotReach()`, once.** The whole URL is treated as secret and the
message is **rebuilt from an allow-list**, not scrubbed. Two things go back in: the **host**, taken
structurally with `parse_url()` — which also drops `user:pass@` userinfo — and the client's
**reason**, cut at the first `://`.

🔴 **The cut is positional, not pattern-based, and that is the whole design.** A redaction that works
by *recognising* secrets — a regex for token-shaped strings, a list of known credential names — fails
silently the first time a network issues a credential shaped differently, and it fails by leaking.
This one never reads the secret. It rests on one property instead: everything the client appends
that came from the request is a URI, and a URI here always begins `scheme://`.

**`str_replace($url, …)` is the obvious alternative and it does not work.** The URI in the message
is the *effective* one, not the `$url` the method was handed: `send()` passes a GET's payload to
`$request->get()`, which appends it as a query string — exactly where VK's token used to live — and
`putBytes()`/`sendMultipart()` are called with URLs Kargah never built at all (VK's `uploadServer()`
hands over a URL VK chose). Removing the string we know still leaves the part we did not.

What survives is `Telegram could not be reached, so the post was not sent: api.telegram.org — cURL
error 28: Operation timed out after 10001 milliseconds`. Host, cURL code and reason intact. **The
cost is the path, and the path is the part that cannot be shown.**

**Every catch site now goes through it — there are no exceptions left.** Two were leaks
(`HttpPublisher`'s four, `MetaGraph`'s one); the rest are hardening, on the principle that the next
endpoint added should not have to remember:

| File | Was it leaking? |
|---|---|
| `HttpPublisher` ×4 (`send`, `sendMultipart`, `sendBytes`, `putBytes`) | 🔴 yes — Telegram |
| `MetaGraph::graphBody()` | 🔴 yes — all three Meta `verify()` calls |
| `WordPressPublisher` ×2 | 🔴 latent — `$base` is operator-typed and can carry `https://user:pass@site/` |
| `LinkedInPublisher`, `DevToPublisher`, `HashnodePublisher` | no — all authenticate in a header |

`grep` for `PublishFailed::unreachable($this->network(), $e->getMessage())` now finds nothing.

**Do not undo the `MetaGraph` line's second half.** It passes `$this->network()` where the old code
passed `$this->graphName()`. `PublishFailed` labels the network *itself*, so the old call was
labelling an already-labelled name and only worked because `Networks::label()` falls back to
`ucfirst()`.

## 3. The three findings the last review left standing

### 3.1 An OAuth nonce was replayed across retries — Tumblr and X

`HttpPublisher::request()` retries the same `PendingRequest`, **headers included**, and both drivers
set the OAuth 1.0a signature as a fixed header computed once. A nonce is single use by definition,
so a conforming server refuses the replay: a transient 503 on attempt one became a **401** on attempt
two, and 401 on the posts page reads as a bad credential. The cost was never a failed post — it was
an afternoon regenerating four credentials that were never wrong.

🔴 **`TRIES = 1` alone was not enough, and this is the part worth carrying forward.** Both drivers
upload through `uploadRequest()`, which reads a **different** constant (`UPLOAD_TRIES`, default 2).
A `TRIES`-only fix leaves every *picture* post still replaying its nonce — the text path fixed, the
media path silently not. Both constants are overridden in both drivers.

**The cost accepted.** A genuine transient failure now fails that target on the first attempt. It is
a delayed post, not a lost one: `PostTarget::FAILED` is not terminal, `claim()` accepts a failed row,
and the posts page and post-show page both offer Retry per-post and per-target. Nothing re-queues it
automatically, so it waits for a person. That was checked, not assumed.

### 3.2 An article cover expired thirty minutes after publication — DEV.to and Hashnode

`AttachmentService::publicUrl()` defaults to a **30-minute** signed link. Both drivers justified
handing over a signed URL by citing Meta's reasoning — but Meta's case is sound only because Meta
**ingests the bytes during the call**. Nothing establishes that DEV or Hashnode do; both fields are
just URLs. If either renders it live, the cover 403s half an hour after publication, on a **public**
article, with `post_targets.status` still reading `published` and nothing in Kargah ever noticing.
Nobody finds out until a reader mentions a broken image.

Now `COVER_URL_MINUTES = 60 * 24 * 365` on both. **One year, and deliberately not "no expiry":**
`data.file-share` sits outside the auth group with the signature as its only protection, so an
unbounded link is a permanent public URL for a private attachment the moment it reaches a referrer
log or a scraper. `AttachmentService`'s 30-minute default is untouched — Instagram and Threads rely
on it and their case is the corroborated one.

⚠️ **This is a named guess, not a fact**, and it is named at the site in both docblocks. The symptom
of it being wrong in the other direction is nothing at all.

### 3.3 VK leaves wall photos behind when the post fails — documented, not changed

`photos.saveWallPhoto` does not stage anything: it files the picture in the wall's own album, where
followers can see it, **before** the post exists and whether or not it ever does. A `wall.post` that
fails on the last of thirty-one requests has still published the pictures.

Accepted, and now written out in `VkPublisher`'s class docblock with the reasoning. Deleting on
failure means `photos.delete` inside a `catch` — a second network call on a path that is already
failing, most likely because VK is unreachable, so the cleanup fails too and the error message
becomes about the cleanup. Uploading after `wall.post` is impossible: the attachment ids are an
argument to it. In practice `wall.post` is the *most* likely of the thirty-one to succeed, since the
uploads have already proved the token, the scopes and the community rights.

## 4. Debts paid

### 4.1 The catalogue now knows which module registers each entry

WordPress, DEV.to and Hashnode have their entries in Social's `Networks` and their drivers registered
by `BlogServiceProvider`. With `Blog` switched off, Social offered three destinations nothing could
send to.

**Two accessors, split on *describe* versus *offer*.** `Networks::all()` is unchanged in shape and
still resolves all seventeen — `HttpPublisher:68` and the registry invariant both depend on that.
`Networks::available()` is the filtered view, and it is **opt-in**, so nothing that reads an existing
row can be broken by it.

- **Offer** → `available()`: the connect picker, and the "networks Kargah supports" invitation.
- **Describe** → `all()`: `⚡calendar`, `⚡notifications`, and the row list in `⚡accounts`. Each
  carries a comment saying why, so the next reader does not "finish the job".
- `⚡publish` is neither — it lists *accounts*, not catalogue entries — so the filter is at `mount()`
  and the row label. It no longer auto-ticks an account whose module is off, which `isConnected()`
  cannot see because the credentials are all still there.

🔴 **A connected account whose module is off keeps its row.** Hiding it leaves a blank where a
connection used to be, with no sentence anywhere, and a stored credential the person can no longer
reach to withdraw. `Networks::unavailableReason()` follows `HttpPublisher::unavailableReason()`'s
precedent and returns the sentence to put under the row. **Disconnect stays; Connect goes** — the
connect page no longer offers that network, and a button landing on the picker instead of the form
it promised is worse than no button.

`Module::find($name)?->isEnabled()`, **not** `Module::isEnabled($name)`: the latter throws
`ModuleNotFoundException` for a module gone from disk rather than merely disabled, which would turn
every page drawing this catalogue into a 500. There was no precedent in the codebase — the only
`Nwidart` references outside `vendor/` are the eight providers' `extends ModuleServiceProvider`.

### 4.2 An article edit page, a factory and a seeder

**A separate `⚡article-edit`, not a mode of the composer.** Teaching `⚡compose` to edit is the
smaller diff, but every step of its `submit()` is a *create* — insert a post, insert an article,
insert a target per destination, attach uploads to a row that did not exist a moment ago, hand it to
`PostPublisher`. A mode flag would put an `if` through `mount()`, `submit()`, `attachTo()` and the
schedule block, in the only file through which anything reaches a network. **A mistake there does not
look like a broken edit page; it looks like an article that publishes twice.**

The price is real and stated in both docblocks: the two files now describe the same four fields, and
a fifth column on `blog_articles` has to be added in both.

🔴 **No driver can update a post it has already made** — `publish()`, `publishWithOptions()`,
`verify()`, and no fourth method anywhere. So a delivered destination is frozen, and **the page says
so on screen**, above the form, not in a toast; each delivered destination is listed with a link to
its own `remote_url`.

**The half that is not obvious.** A save rewrites `post_targets.options` — but **only** on targets
that have not published and that already carry a bag. The title lives twice, on `blog_articles` and
in the options bag, so correcting it here and leaving the bag alone would publish the **old** title
next Tuesday with the corrected one sitting in the database looking right. A published target's bag
is left exactly as sent: it is the record of what was actually sent, and rewriting it destroys the
only evidence of it.

⚠️ **`Article::factory()` needs the `newFactory()` override**, which is now on the model.
`Factory::resolveFactoryName()` looks for `Database\Factories\Modules\Blog\Models\ArticleFactory`,
which is not where a module keeps anything. Without it the method simply does not exist.

🔴 **`Article::factory()->make()` writes to the database.** It resolves a nested `Post::factory()` by
**creating** the row. The obvious `tinker --execute` check to confirm the factory resolves will
insert a post into the owner's dev database unless it is wrapped in a transaction and rolled back.

`BlogDatabaseSeeder` is registered in `database/seeders/DatabaseSeeder.php` **after**
`SocialDatabaseSeeder`: it hangs a teaser target on whichever short-form account already exists and
creates none of its own.

### 4.3 The per-card deep link — and it was a worse bug than recorded

The 5 August handover called this a missing feature. It was a **broken** one.
`BoardReader.php:243` and `CardReader.php:28` already built `route('projects.boards', [… 'card' => $id])`
— but `⚡boards.blade.php` declared no `card` URL property, so the parameter was accepted by the
router, ignored by the component, and the person landed on the board with the card **closed**. A link
that looks like it works and silently does not.

`#[Url(as: 'card', except: '')]` plus `openDeepLinkedCard()` in `mount()`. `Watching::cardUrl()`
(the notification builder — the thing the handover was actually complaining about), both
`BoardCalendar` events, and `Mailbox`'s `⚡inbox::cardUrl()` now all emit it.

🔴 **The authorisation reasoning matters more than the feature.** `cardOnThisBoard()` guarantees one
thing: the card has a placement on a non-archived list of the *currently open* board. It deliberately
does **not** exclude archived cards, so `isArchived()` is layered on top. The card is resolved
strictly against the board named in the same URL rather than switching boards to follow the card —
the latter would make `?card=` alone a table-walking primitive. **Kargah has no board-membership
model at all**: no policy, no gate, `Board::active()` with no user scoping, `members()` returns every
`User`. So "on the board named in this same URL" is the only boundary that exists.

A refusal raises **one** `toastError` with the **same** sentence for all five cases (other board,
archived, deleted, never existed, non-numeric). Distinguishing them would answer "does card 4,102
exist?" for anybody willing to type. Silence would have replaced the handover's complaint with the
identical bug wearing a deep link.

## 6. What was verified, and how

Full suite: **1,199 tests, 5,775 assertions, all passing** — 426 seconds. Baseline was 1,171 / 5,670,
so this session added 28 tests and 105 assertions. That was run by the main thread at the end, once,
after every agent had reported; no agent's claim about the full suite was taken on trust, and none
was asked to run it.

🔴 **Four invariants were mutation-tested by the main thread** — the code was deliberately broken, the
test confirmed to fail, and the code restored. A green suite proves a test runs; only this proves it
would catch the bug it was written for.

| Invariant | Mutation | Result |
|---|---|---|
| Meta token cannot reach a failure message | restored `$e->getMessage()` in `MetaGraph::graphBody()` | failed, **with the token visible in the failure text** |
| Catalogue entry names its registering module | flipped DEV.to's `module` to `Social` | failed: *"devto names Social but is registered from Blog"* |
| A deep link cannot open a card on another board | replaced `cardOnThisBoard()` with `Card::find()` | failed: *"an event [open-card] was not fired"* |
| An archived card cannot be deep-linked | removed the `isArchived()` guard | failed (by the subagent, reproduced message) |

`NetworkRegistryTest`'s new invariant deserves a note: it asks the **registration**, not the class.
It reflects on the closure `Publishing::extend()` was handed and asks PHP which **file** that closure
was written in — literally "the provider that registers this driver". Reading the driver's namespace
instead would be a proxy, and it would pass for the one arrangement the design forbids: a
`Modules\Blog` class registered from Social's provider.

## 7. 🔴 Still true: not one driver has ever been called for real

Unchanged from 5 August and it governs everything above. There is **no CA bundle in this machine's
`php.ini`**, so outbound HTTPS from PHP fails with cURL error 60. Every request shape in this
codebase is proved with `Http::fake()` and `Http::preventStrayRequests()` and nothing else.

**The first real post on each network is still the highest-value work available.** The credential
steps per network, with the traps, are in `HANDOVER-2026-08-05.md` §3 — Slack's `/invite`, VK's
`offline` scope, Meta's long-lived exchange, Lemmy's two-factor, Hashnode's un-prefixed
`Authorization`. The uncorroborated lists in each driver's docblock name the likely failures.

Specific to this session, and unprovable here:

- Whether DEV.to or Hashnode **ingest** the cover URL or render it live. The whole of §3.2 is a bet
  on the second.
- The exact wording of a real Guzzle/cURL failure. The redaction's fixture reproduces Guzzle 7's
  documented shape read out of `CurlFactory`; no real timeout can be produced here.
- Whether a live Tumblr or X server refuses a replayed nonce with **401** specifically rather than
  some other refusal.
- Behaviour with `modules_statuses.json` genuinely edited. The tests stub the repository rather than
  writing to that file, because it is live configuration and a test that failed halfway would leave
  the install missing a module.

## 9. Process notes for the next session

**The subagent structure earned its place again** and the three rules that mattered were, in order:
exclusive file ownership decided before anything launched; one shared brief in the scratchpad that
every agent read before its own prompt; and the main thread verifying every report itself. Two agents
mutation-tested their own work unprompted, which is the habit worth reinforcing in the brief.

🔴 **The working directory reverts to `C:\Users\morph\Projects\Visa` between shell calls, and it will
catch you.** It caught this session: a `git status` without an explicit `cd` reported a **clean tree**
in the wrong repository, which for about a minute looked like six agents' work had been wiped. `cd`
explicitly in every single shell call, including the ones that feel too small to bother with —
especially `git`, where the wrong answer is indistinguishable from a catastrophe.

⚠️ **Scripted edits with Python change line endings.** Several files here were patched with a Python
script for precision on repeated strings; `pint` then reported `line_ending` fixes on all of them.
Git's normalisation kept the diffs proportional, but check `git diff --stat` after any scripted edit
before believing the change is small.
